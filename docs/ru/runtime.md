# Запуск и ошибки

`app.Run(ctx, args, opts...)` запускает корневую команду. `args` содержит слова после имени программы.
Метод возвращает ошибку вызывающему коду. Сам он выводит только help, version и предупреждения об устаревших командах или flags.

```go
var out, errOut bytes.Buffer
err := app.Run(
	context.Background(),
	[]string{"--port", "8080"},
	cli.WithStdout(&out),
	cli.WithStderr(&errOut),
	cli.WithEnv(func(name string) (string, bool) { return "", false }),
)
```

`WithStdin`, `WithStdout`, `WithStderr` и `WithEnv` действуют только в текущем вызове.
По умолчанию используются `os.Stdin`, `os.Stdout`, `os.Stderr` и `os.LookupEnv`.
В обработчиках, wrappers и checks потоки доступны через `cli.Stdin(ctx)`, `cli.Stdout(ctx)` и `cli.Stderr(ctx)`.

## Порядок обработки

1. Возвращаются ошибки схемы, если они есть.
2. Разбираются слова командной строки. Ошибка разбора имеет приоритет перед `--help`.
3. Запрос `--help` или `--version` выводится в stdout без проверки обязательных значений и без запуска обработчика.
4. Если у выбранной команды нет `run`, возвращается `*cli.InputError`.
5. Значения берутся из командной строки, окружения или default.
6. Проверяются required flags, допустимые значения и checks.
7. Запускаются wrappers и обработчик.

Flag предка можно указать до или после имени подкоманды. Невыбранные команды не получают значения и не проходят checks.

## Ошибки

Ошибки объявлений доступны через `app.Err()`, `Run` и `Complete`. Каждая ошибка имеет тип `*cli.SchemaError` и поле `Pos` вида `file.go:line`.
Ошибка ввода имеет тип `*cli.InputError`. Поле `Path` содержит путь выбранной команды.
Ошибки обработчика и wrappers возвращаются без преобразования.

```go
if err := app.Run(ctx, words); err != nil {
	var input *cli.InputError
	if errors.As(err, &input) {
		fmt.Fprintf(os.Stderr, "неверный ввод для %s: %v\n",
			strings.Join(input.Path, " "), input)
		return
	}
	fmt.Fprintln(os.Stderr, err)
}
```

В `func main` вызовите `os.Exit(app.Main())`. `Main()` берёт `os.Args[1:]` и печатает ошибки в stderr.

| Exit code | Причина |
| --- | --- |
| `0` | Успешный запуск. |
| `2` | Ошибка ввода. |
| `130` | Запуск завершился с `context.Canceled`. |
| `1` | Другая ошибка. |

Первый `SIGINT` или `SIGTERM` отменяет context. После второго сигнала действует обычное завершение процесса.

## Повторные вызовы

Каждый узел хранит одну структуру аргументов на время жизни приложения. Перед `Run` и `Complete` связанные поля сбрасываются.
Последовательные вызовы допустимы. Одновременные вызовы одного приложения возвращают ошибку.
Если данные нужны после вызова, скопируйте их внутри обработчика.

`Run` и `Complete` вызываются только на корне дерева.
`Builder` действует только во время `bind`. Изменение схемы после возврата из `bind` даёт ошибку схемы.
